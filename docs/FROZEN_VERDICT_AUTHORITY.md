## 3. 什么 **不算** 改判

下列操作 **不改变** L1 冻结判定：

1. **措辞降调或加强**：如 P4 不写「核排斥驱动」、P9 写「趋势层」、P5 不写「恒正」——只收窄**解释边界**，不改变「是否达预注册阈值」。
2. **阅读辅助五态标签**（见 §4）：与冻结二元判定**并存展示**，不替换 L1。
3. **补 metadata**：JSON 补 `quality_gate`、`code_commit`、schema 校验——工程加固，不改数值与阈值结论。
4. **第三方评审回应**：采纳改进建议 ≠ 推翻冻结；除非走完 §5 改判程序。
5. **README / 徽章 / Agent 叙事**：从「validated」改为「evidence package」等——**不改变 L1**。
6. **P2 身份澄清**：标明「元命题 / 派生汇总」——**不改变 P2=一致**。

## 5. 唯一合法的改判程序

仅当 **同时** 满足下列条件，才允许修改某命题 L1 判定：

1. **新证据**：新计算或纠正方法学错误后的重算（非仅改文案）。  
2. **预注册**：新阈值或新判据须先写入 `implementation/` 或 `docs/propositions.md`（不得事后放宽迁就数值）。  
3. **质控**：G1–G5 全过；`quality_gate.passed == true`。  
4. **落盘**：更新 `deliverables/unit/Pn/VERDICT.md` → 同步 `VERDICT_TABLE.md` → 结题包 → **不得**只在 README 改口。  
5. **审计**：若判定翻转，须说明与冻结版差异原因（如 P3 事故链范式）；旧版判定保留于 git 历史，不静默删除。

**禁止**：用聊天结论、第三方评审意见、五态标签、或首页措辞修订 **单独** 改写 L1。
